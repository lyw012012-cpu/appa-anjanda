# 오프라인 파이프라인 설계 (I-2)

> 소리 목록과 원본을 넣으면 `python -m src.build_sounds` 한 번으로 `sounds.json`·소리 파일·`sound-assets.ts`를 만든다. 모든 특징은 **고정 기준**이라 소리가 늘어도 기존 값이 바뀌지 않는다.

근거: [ai-design.md(PR #7)](https://github.com/lyw012012-cpu/appa-anjanda/pull/7) 6절(단계·환경·6.2 실험), [contracts.md](contracts.md) C1~C3(입출력 모양·검사 규칙). 이 문서는 그 위에 계산식과 만드는 방법을 정한다. 작성 2026-11-18.

표시: **[결정]** 사용자가 정함 / **[제안]** 설계자가 채움, 구현자가 근거와 함께 바꿀 수 있음 / **[가설]** 실험으로 확인할 값

## 1. 왜, 무엇을

- 앱은 휴대폰에서 신경망을 돌리지 않는다(M1). 소리를 이해하는 일(YAMNet 임베딩, 음향 특징)은 PC에서 미리 해서 숫자로 넘긴다.
- 앱의 밴딧은 특징마다 가중치를 배운다(C8). 그래서 **특징 값의 뜻이 바뀌면 배운 가중치가 엉뚱한 소리를 가리킨다.** 특징은 사람과 무관한 "소리를 재는 자"이고, 사람별 차이는 앱의 가중치·처음 설정·"이 소리 빼기"가 맡는다.

### 목표

- C2·C3 규칙을 지키는 출력을 명령 하나로, 같은 입력이면 같은 결과로 만든다(실행 시각인 `generatedAt`만 예외)
- 음높이·거슬림·520 닮음·유사도 영점을 **고정 기준**으로 계산한다 [결정]
- I-2 완료 조건: 코사인 분포 그림, E2 순위 표, 결론 한 단락

### 하지 않는 것

- YAMNet 재학습·미세 조정, 파이프라인 안의 학습 (학습은 앱의 가중치 5개뿐)
- PCA 축소(6.3 ⑥, MVP 밖), 세 쌍 비교 E1(I-12)
- 앱 코드 변경. 고정 영점은 앱이 `model.simMedian`을 읽기만 해서 바꿀 것이 없다. C8 규칙 3(`sim520n` 정규화 빼기)은 추천 코드에 영향을 주지만, 그 코드는 아직 없으므로 I-7이 바뀐 계약대로 짠다

### 실패로 보는 것

- 소리를 하나 추가했더니 기존 소리의 `pitch`·`harshness`·`sim520`·영점이 바뀜
- 출력 파일을 손으로 고쳐야 앱이 돌아감(M5)
- 명령 한 번으로 다시 만들 수 없음

## 2. 만드는 방법

| | 방법 | 판단 |
|---|---|---|
| **A** | 스크립트 하나(`src/build_sounds.py`), 단계마다 함수, 끝에 C2 검사 후 쓰기. 기준 소리 pytest | **선택** [결정]. 파일이 적고 누구나 명령 하나로 재생성 |
| B | 단계별 파일 + 중간 결과(npz) 저장 | 소리 30개면 YAMNet이 몇 초라 저장할 이유 없음 |
| C | 노트북 중심 | 실행 순서에 따라 결과가 달라지고 리뷰가 어려움. C2의 "명령 하나" 규칙과 맞지 않음 |

## 3. 입력과 출력

| | 위치 | 규칙 |
|---|---|---|
| 입력 | `ai/data/sounds.csv`, `ai/data/sounds/` (git 제외) | C1. 라이선스 빈칸이면 그 줄에서 멈추고 id를 적은 오류 |
| 출력 1 | `app/src/data/sounds.json` | C2 |
| 출력 2 | `app/assets/sounds/<id>.mp3` | C3. mp3, 모노, 44.1 kHz, **64 kbps 고정**(30초 × 30개 ≈ 7 MB), 30초 이하, 전체 10 MB 이하 |
| 출력 3 | `app/src/data/sound-assets.ts` | C3. 생성 파일임을 맨 위 주석에 적음 |
| 보고 | `ai/reports/` (커밋함, 작은 png·md만) | 코사인 분포 그림, E2 표, 상관 R10, 실제 목록의 쌍별 중앙값 |

명령: `cd ai && python -m src.build_sounds --csv data/sounds.csv --app ../app` (C2). 실제 소리가 없을 때(I-3 전)는 `--synthetic`으로 E2 대조 소리와 차임을 입력 대신 써서 파이프라인을 끝까지 돌려 본다 [제안].

- **출력은 `ai/out/`(git 제외)에만 쓰고 `app/`에는 쓰지 않는다.** 백색 잡음 같은 대조 소리가 앱의 알람 후보가 되면 안 되기 때문이다. 앱 개발은 그동안 `app/src/data/sounds.fixture.json`(contracts 8절)을 쓴다
- C1 열은 코드가 채운다: 길이 3초, `license` `자체 제작`, `source_url` `-`, `group`은 차임 `melody`·백색 잡음 `other`·나머지 `beep`, 계열마다 첫 소리가 `group_rep`
- 합성 소리는 C1의 "계열마다 3개 이상"을 채우지 못하므로, 이 검사만 합성 모드에서 건너뛴다. 나머지 C2 검사는 그대로 한다

## 4. 단계

```
sounds.csv 한 줄
 → ① 읽기·맞추기 ─┬→ 44.1 kHz 파형 → ⑦ mp3 쓰기
                  └→ 16 kHz 파형 → ② YAMNet → embedding, top3
                                 → ③ 음향 특징 → pitch, harshness, sim520.hand
                                 → ④ 520 닮음 비교용 → sim520.emb, sim520.mel
 전체 → ⑤ 영점·검사 → ⑥ 보고 → ⑦ 쓰기
```

### ① 읽기·맞추기
- `soundfile`로 읽고(wav·mp3·ogg·flac 모두 됨, ffmpeg 불필요 — 2026-11-18 이 PC 확인) 모노로 섞는다
- 앞뒤 무음만 자른다(`librosa.effects.trim`, 기준 −40 dB [제안]). 삑-쉼 사이 쉼은 유지
- 30초를 넘으면 30초에서 자르고 끝 50 ms를 줄인다 [제안]
- 음량(C3): RMS −20 dBFS로 맞추고, 피크가 −1 dBFS를 넘으면 그만큼 낮춘다 [가설]. **RMS는 소리가 나는 구간만으로 잰다**(최대 프레임보다 40 dB 넘게 작은 프레임은 뺀다 [제안]). 쉼까지 평균하면 삑-쉼 소리가 다른 소리보다 크게 맞춰지기 때문이다
- 맞춘 파형을 44.1 kHz(앱 파일, 날카로움)와 16 kHz(YAMNet, 음높이, 거칠기, 520 닮음) 두 벌로 만든다. **모든 특징은 맞춘 파형으로 계산한다**(C3). YAMNet 입력만 4초보다 짧으면 반복해 4초로 만든다(C3, 2026-11-20 측정: 1초 미만 14개, 원래와 반복의 YAMNet 코사인 0.52~0.98, 반복 4초와 10초는 0.97 이상으로 거의 같음)

### ② YAMNet [결정, 6.1 확인됨]
- `tensorflow_hub`로 YAMNet을 읽는다. 내려받는 곳은 `ai/models/`(git 제외, `TFHUB_CACHE_DIR`)
- 조각별 임베딩 `[N×1024]`을 평균 → L2 정규화 → `embedding`
- 조각별 점수 `[N×521]` 평균의 상위 3개 클래스 이름(영어 원문) → `top3`

### ③ 음향 특징 (고정 기준) [결정: 고정 기준 / 제안: 계산식]

#### 음높이 `pitch`

- `librosa.pyin`(65~4200 Hz)으로 소리가 나는 구간의 기본음을 찾아 중앙값 f를 쓴다
- `pitch = clip((log2 f − log2 100) / (log2 4000 − log2 100), 0, 1)` → 100 Hz = 0, 4000 Hz = 1, 520 Hz ≈ 0.447
- 기본음이 잡힌 구간이 30% 미만이면(잡음·자연음, 이하 "기본음 없음") **`pitch` = 0.5(모름)**. 스펙트럼 무게중심으로 대신하면 거슬림의 날카로움과 같은 값이 되어, 가중치가 이 소리들의 음높이에서 엉뚱한 것을 배우기 때문이다

#### 거슬림 `harshness`

- 날카로움 s: **44.1 kHz 파형**의 스펙트럼 무게중심(Hz) 중앙값을 로그 눈금으로(100 Hz → 0, 8000 Hz → 1, 밖은 자름). 16 kHz 파형에는 8 kHz 위 소리가 없어 휘슬 같은 고음이 덜 거슬리게 계산되기 때문이다
- 거칠기 r: 진폭 포락선 e(t)(힐버트 변환)를 2 kHz로 줄이고 15~300 Hz로 대역 통과한 것을 ẽ(t)라 할 때 `r = clip(√2 × RMS(ẽ) / mean(e), 0, 1)`. **평균 크기 대비 떨림 깊이**라 떨림 없는 순음은 0, 100% 진폭 변조는 1이다(비율로 재면 떨림이 거의 없는 소리에서 아주 작은 값끼리 나눠 값이 튄다)
- 원점수 `raw = 0.5 s + 0.5 r` [가설]
- 기준 소리 두 개로 고정해 0~1: `harshness = clip((raw − raw₀) / (raw₁ − raw₀), 0, 1)`
  - 0점 `raw₀`: 부드러운 차임(`proto_sounds.py`의 C-E-G 차임)
  - 1점 `raw₁`: 3 kHz 사각파를 70 Hz로 100% 진폭 변조한 버저
  - 두 값은 코드에 **상수로 박는다**. 기준 소리를 만드는 함수와 상수가 맞는지 pytest가 확인
- 평균적인 사람의 경향일 뿐 개인 혐오감이 아니다. 팀 3명의 1~5점 평가와 순위 상관을 본다(PR #7 6.4, E6). 0.5 미만이면 식을 고친다 [가설]
- 알려진 빈틈: 이 식은 알람에서 흔한 **"삑-삑-삑" 반복(초당 2~8번)**과 **갑자기 터지는 시작음**을 재지 않는다. 팀 평가가 어긋나면 이 두 항목을 이 순서로 먼저 더해 본다 [가설]

#### 520 닮음 `sim520.hand`

- `hand = 가까움 × 음색`. 기본음 없음이면 0
- 가까움: `exp(−(log2(f / 520))² / (2 × 0.273²))` → 520 Hz = 1, 400·650 Hz ≈ 0.5
- 음색: 배음 k = 1~9의 진폭을 재고, k = 2~9 진폭 벡터와 사각파 벡터(홀수 k만 1/k)의 코사인을 c라 할 때 `0.5 + 0.5 c`
  - **k = 2~9 배음 에너지의 합이 기본음 에너지의 1% 미만이면 "배음 없음"으로 보고 c = 0**. 0에 가까운 벡터로 코사인을 내면 값이 아무렇게나 나오기 때문이다
  - 사각파 1, 순음 0.5, 톱니파 ≈ 0.79

### ④ 520 닮음 비교용 (E2용)
- `emb`: 520 Hz 사각파 3초(코드로 생성)의 YAMNet 임베딩과의 `max(0, 코사인)`
- `mel`: 로그 멜(64칸)의 시간 평균에서 칸 평균을 뺀 벡터끼리 `max(0, 코사인)` (6.2: 빼지 않으면 무음·음량에 끌려감)
- 앱 기본값은 `hand`(C9 `sim520Method`). 둘은 비교 기록용

### ⑤ 영점·검사
- **유사도 영점 `model.simMedian` = 상수 0.58** [결정]. 6.2 합성 소리 36쌍의 중앙값. 목록으로 다시 계산하지 않는다
- I-3이 끝나면 실제 목록의 쌍별 `max(0, 내적)` 중앙값을 ⑥ 보고에서 보고, 그 값으로 **한 번** 바꿔 고정한다(그 PR에 근거 한 단락). 그 뒤로는 소리가 늘어도 바꾸지 않는다
- 소수 반올림(임베딩 5자리) 뒤 C2 표 규칙 전부를 assert: ID 형식·중복·정렬, 임베딩 길이와 L2 노름 1 ± 1e-3, 0~1 범위, `group_rep` 계열마다 1개, 파일 이름 일치. 어기면 어느 규칙·어느 id인지 적고 **아무 파일도 쓰지 않는다**

### ⑥ 보고 (`ai/reports/`)
- `cos_hist.png`: 서로 다른 쌍의 `max(0, 내적)` 분포, 영점 0.58 선
- `report.md`: E2 순위 표, 실제 목록의 쌍별 중앙값, 소리별 특징 표
- **2단계 후보 수**: 소리마다, 영점 조정한 유사도가 `contrastMaxSim`(0.5) 이하인 다른 소리의 수. 0인 소리가 많으면 실제 알람 소리끼리 너무 비슷해 대비 단계가 자주 조건을 푼다는 뜻이다. I-3 뒤 영점을 정할 때 이 숫자를 함께 본다
- **`pitch`–`sim520.hand`**: 상관계수(R10: |r| > 0.7이면 경고하고 팀에 알림)와 **산점도 `pitch_vs_hand.png`**. 520 닮음은 같은 기본음의 종 모양 함수라 직선 상관이 낮아도 겹칠 수 있으므로 사람이 그림을 본다. 뺄지는 I-13에서 판단
- E2 대조 소리 5개 [제안]: 520 Hz 사각파, 520 Hz 삑-쉼, 500→3000 Hz 미끄럼, 3100 Hz 순음, 백색 잡음. 세 방식(`emb`·`mel`·`hand`)이 각각 매긴 순위

### ⑦ 쓰기
- `sounds.json`(id 오름차순, `generatedAt`은 기기 현지 오프셋 포함), mp3, `sound-assets.ts`를 쓴다
- mp3는 `soundfile`로 모노 64 kbps 고정 비트레이트로 쓴다. 전체 크기가 10 MB를 넘으면 실패

## 6. 검사 (pytest)

| 검사 | 기대 |
|---|---|
| 520 Hz 사각파 | `pitch` ≈ 0.447, `sim520.hand` ≥ 0.95 |
| 520 Hz 순음 | `sim520.hand` 0.4~0.6, 거칠기 r ≤ 0.05 |
| 3 kHz 사각파 | `sim520.hand` ≤ 0.05 |
| 백색 잡음 | 기본음 없음 → `sim520.hand` 0, `pitch` 0.5 |
| 차임 / 버저 | `harshness` 0 / 1, 상수 `raw₀`·`raw₁`과 일치 |
| 10 kHz 순음 | 날카로움 s = 1 (44.1 kHz로 잼) |
| 음량 | 같은 520 Hz 삑을 쉼 길이만 바꿔 두 개 만들면, 맞춘 뒤 소리 나는 구간의 RMS가 서로 같음(±0.5 dB) |
| 고정 기준 | 소리 목록에 소리 하나를 더해도 기존 소리의 `pitch`·`harshness`·`sim520`·`simMedian`이 같음 |
| C2 검사 | 하이픈 든 id, 노름 어긋난 임베딩 → 오류이고 파일을 쓰지 않음 |
| 합성 모드 | 출력이 `ai/out/`에만 생기고 `app/`은 그대로 |
| 용량 | 30초 소리의 mp3가 64 kbps 기준 크기(약 240 KB ± 10%) |

YAMNet을 쓰는 검사는 느리므로 표시(`@pytest.mark.yamnet`)를 달아 따로 돌릴 수 있게 한다 [제안].

contracts 9절대로 **계약 변경이 코드보다 먼저**다. 파이프라인 코드 PR을 올리기 전에 아래 표를 PR #9(작성자 yj2trigger)에 전달해 반영하거나, 별도 `docs(contract):` PR로 올린다.

|---|---|---|
| C2 `pitch` | 목록 안 최소-최대 정규화, 기본음 없으면 스펙트럼 중심 | 100~4000 Hz 로그 눈금 고정, 기본음 없으면 0.5(3절 ③) |
