# 설계 문서

> 과기부 × 엘리스 AI 챌린지 "일상 속 문제, AI로 해결하다", 마감 **2026-11-22**, 3명. 제출물은 **기획안 + PoC**.
> 요구사항 → 구조 그림 → 아키텍처 결정 → 상세 설계 → 이슈 나누기 순서로 쓴 문서다.

## 한 줄

**YAMNet이 소리를 이해하고, 밴딧이 사람을 이해한다.** 혐오감 없이 편안하게, 그러나 반드시 깨우는 알람. 알람 한 번에 소리 3개를 편안함 → 대비 → 낯섦 순서로 들려주고(세기가 아니라 낯섦으로 깨움), 끈 뒤 "지금 어떠세요?"와 재확인으로 다시 잠든 것을 잡는다. 사람마다 "어떤 성질의 소리(낮은 음, 520 Hz 사각파를 닮음, 낯섦)가 나를 깨우나"를 반응 기록으로 학습한다. 원안은 [ai-design.md(PR #7)](https://github.com/lyw012012-cpu/appa-anjanda/pull/7).

## 문서 색인

```
docs/
├── context/        컨텍스트: 무엇을 왜 만드나, 3명 사이 약속, 할 일
│   ├── design.md
│   ├── contracts.md
│   └── issues-draft.md
├── architecture/   아키텍처 제약: 구조 규칙과 도구로 막는 방법
│   └── README.md
└── system/         시스템 제약: 타입 검사·린트, 자동 테스트, 검증 다각화
    ├── README.md
    └── design-checklist.md   설계·점검 체크리스트 (실제로 생긴 허점 모음)
```

| 폴더 | 문서 | 담는 것 | 단계 |
|---|---|---|---|
| 컨텍스트 | [design.md](context/design.md) | 범위, 드라이버·품질 목표, 가정·위험, 그림, 아키텍처 결정(권장), 상세 설계(점수 공식·데이터 계약), **구현하면서 하는 실험 표** | 요구사항·설계 |
| 컨텍스트 | [contracts.md](context/contracts.md) | **3명 사이의 모든 계약**: 공유 타입, 함수 모양, 파일·저장 위치, 판정 규칙, 설정, 가짜 데이터와 기대 결과, 계약 변경 절차 | 상세 설계 |
| 컨텍스트 | [issues-draft.md](context/issues-draft.md) | 이슈 초안, 의존성 그래프, 담당 제안, 마일스톤 | 이슈 나누기 |
